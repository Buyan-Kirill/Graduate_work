# Agent Entry Point

Этот файл обязателен к прочтению перед работой в репозитории.

## Порядок чтения

1. `.agents/PROJECT_GOALS.md` — цели проекта и критерии качества.
2. `.agents/CURRENT_STATUS.md` — актуальное состояние и последний проверенный
   результат.
3. `.agents/TASKS.md` — разрешённые, ожидающие решения и запрещённые сейчас
   действия.
4. `.agents/DECISIONS_AND_INCIDENTS.md` — краткий журнал важных решений,
   результатов и ошибок.
5. `PROJECT_HANDOFF.md` — подробная историческая память и старые runbook.
6. Ближайшие README, protocol, ledger и `run_note.md` конкретного эксперимента.

`plans.md` относится преимущественно к SuperSimpleNet/MVTec и не является
текущим планом FastFlow printer study.

## Обязательные правила

- Не выдумывать метрики, результаты, причины ошибок или состояние запусков.
  Любое число должно иметь источник: CSV/JSON/TXT, график или вывод программы.
- Разделять факты, интерпретации и гипотезы. Отрицательные результаты
  сохранять и включать в выводы.
- Не удалять и не перемещать датасеты, эксперименты или пользовательские
  файлы без явного разрешения. По ранее заданному правилу допустимо только
  создавать новые файлы/папки и копировать без перезаписи, если текущая задача
  это разрешает.
- Не перезаписывать historical runs. Новый запуск получает новый каталог.
- Использовать `.venv\Scripts\python.exe` и существующие функции/notebook
  проекта. Не менять системные, VPN, proxy, credential или Git-настройки.
- Git push выполнять только по HTTPS
  `https://github.com/Buyan-Kirill/Graduate_work.git` и только когда это
  разрешено текущей задачей. Временное отключение proxy допустимо только в
  окружении одной команды; настройки не менять.
- Перед training/test проверять clean worktree, provenance, manifest SHA,
  свободную GPU и отсутствие другого Python training process.
- GPU training не запускать параллельно. Текущий FastFlow data study достиг
  hard stop 15 обучений; новые обучения в этой серии запрещены без нового
  явного решения пользователя.
- Не выбирать гиперпараметры по test. Раскрытый test считать
  ретроспективным. Для confirmatory-вывода нужен новый независимый holdout.
- Независимой единицей считать исходную съёмку/source group, а не tiles.
  Остаточные tiles уже использованной съёмки не образуют новый holdout.
- Большие веса/checkpoints не добавлять в Git. Сохранять компактные
  provenance, config, raw scores, metrics, plots, report и описание run.
- Перед изменением файлов сообщать пользователю, что именно будет изменено.
  Важные шаги и отклонения кратко докладывать в процессе.

## Поддержание памяти

После важного подтверждённого действия:

- обновить `.agents/CURRENT_STATUS.md`, если изменилось актуальное состояние;
- обновить `.agents/TASKS.md`, если задача закрыта, заблокирована или добавлена;
- добавить краткую запись в `.agents/DECISIONS_AND_INCIDENTS.md`;
- не копировать туда неподтверждённые числа;
- давать ссылку на первичный артефакт вместо дублирования длинного отчёта.

Если инструкция пользователя конфликтует с этим файлом, следовать более новой
явной инструкции пользователя, кроме системных ограничений безопасности.
